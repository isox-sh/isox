Define commands in each project's `project.json`, then run them from anywhere
inside your workspace. Keep your package manager and the tools you already use.

```sh
npx isox build web
npx isox affected --target=test --base=origin/main
```

## A small configuration surface

An `isox.json` file marks the workspace root. Each `project.json` describes the
commands available for that project. A command can wrap an existing script or use
an executor that integrates directly with a tool.

```json apps/web/project.json
{
  "name": "web",
  "executors": {
    "build": {
      "executor": "core:run-command",
      "options": {
        "command": "npm run build",
        "cwd": "apps/web"
      }
    }
  }
}
```

The example runs the existing `build` script in `apps/web`. Use
[named configurations](/docs/cli#named-configurations) for different environments.

## From local development to CI

Isox discovers project dependencies from source imports, TypeScript aliases,
local package references, and explicit declarations. Use that graph to select
changed projects and their dependents, then distribute work across weighted
GitHub Actions jobs.

## Extend your tooling

Use the built-in [shell executor](/docs/shell-commands), or install native executors
for [TypeScript](/docs/typescript), [ESLint](/docs/eslint), and [Vitest](/docs/vitest).
Write [custom executors and initializers](/docs/custom-executors) when your workflow
needs its own integration, and verify them with the
[plugin testing helper](/docs/plugin-testing).
